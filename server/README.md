# Серверная часть «Делом»

Сервер хранит общие данные платформы и проверяет правила, которые нельзя доверять браузеру: кто что видит, кто что может менять, сроки ответа и лимиты.

Сделано на Django и PostgreSQL. Запускается одной командой через Docker.

## Что умеет

| Раздел | Что делает |
|---|---|
| Вход и роли | Регистрация студента и работодателя, вход по почте и паролю. Ментора, вуз и администратора добавляет администратор. |
| Проекты | Компания публикует проект. Студент вступает, загружает файл и итог, отправляет на проверку. |
| Проверка | Ментор ставит оценки по критериям компании, подтверждает навыки или возвращает на доработку. |
| Паспорт навыков | У каждого навыка есть основание: проект, компания, оценка, ментор. Публичная страница по ссылке. |
| Вакансии и отклики | Вилка зарплаты обязательна. Студент — не больше 5 откликов в неделю. Компания отвечает каждому, отказ — с причиной. |
| Автозакрытие | Нет ответа на отклик 7 дней — позиция закрывается сама и открывается, когда ответили всем. |
| Воронка найма | Приглашение, интервью, оффер, найм — по порядку. Отказ — с причиной. |
| Страница компании | Доля ответов, срок ответа, число наймов, отзывы тех, кто делал проект или был на интервью. |
| Сообщения | Переписка компании и студента после отклика, проекта или приглашения. |
| Вуз | Видит только своих студентов и только тех, кто разрешил делиться прогрессом. |
| Админка | `/admin/` — все данные в таблицах: можно смотреть, искать и править без программиста. |

Список всех запросов с описанием полей: `/api/docs/` на работающем сервере.

## Запуск на сервере

Нужен VPS с Ubuntu и домен, у которого A-запись указывает на IP сервера.

1. Подключитесь к серверу и установите Docker:

   ```
   curl -fsSL https://get.docker.com | sh
   ```

2. Скачайте проект:

   ```
   git clone https://github.com/SanminKim/delom.git
   cd delom/server
   ```

3. Создайте файл настроек и заполните три строки — домен, секретный ключ и пароль базы:

   ```
   cp .env.example .env
   nano .env
   ```

   Случайные значения получаются командами `openssl rand -base64 48` и `openssl rand -hex 24`.

4. Запустите:

   ```
   docker compose up -d --build
   ```

   Через одну-две минуты сайт откроется по адресу `https://ваш-домен`. Сертификат HTTPS выдаётся и продлевается автоматически.

5. Создайте администратора и начальные данные:

   ```
   docker compose exec web python manage.py createsuperuser
   docker compose exec web python manage.py seed_demo
   ```

   Вторая команда создаёт навыки, две компании, вуз, по одному пользователю на каждую роль и печатает их пароль.

После этого работают: `https://ваш-домен/admin/` — админка, `https://ваш-домен/api/docs/` — описание запросов.

## Обслуживание

| Задача | Команда (в папке `delom/server`) |
|---|---|
| Обновить до свежей версии | `git pull && docker compose up -d --build` |
| Копия базы данных | `docker compose exec db pg_dump -U delom delom > backup.sql` |
| Посмотреть журнал ошибок | `docker compose logs web --tail 100` |
| Остановить | `docker compose down` |

Делайте копию базы регулярно и храните её не на этом же сервере.

## Разработка и тесты

```
pip install -r requirements.txt
DEBUG=1 python manage.py migrate
DEBUG=1 python manage.py seed_demo
DEBUG=1 python manage.py runserver
DEBUG=1 python manage.py test core
```

Без `DATABASE_URL` используется файл SQLite. Тесты (`core/tests/`) проверяют сценарии и права доступа: чужая компания не видит чужих откликов, студент не видит чужих решений, вуз не видит студентов другого вуза.

## Устройство

| Файл | Что внутри |
|---|---|
| `core/models.py` | Таблицы: пользователи, компании, проекты, решения, навыки, вакансии, отклики, воронка |
| `core/services.py` | Правила продукта: сроки, лимиты, порядок этапов, подтверждение навыков |
| `core/views.py`, `core/urls.py` | Запросы API и права доступа |
| `core/serializers.py` | Какие поля отдаются и принимаются |
| `core/admin.py` | Админка |
| `delom/settings.py` | Настройки, включая правила манифеста в конце файла |
| `docker-compose.yml`, `Caddyfile` | Запуск на сервере: база, сервер, фоновая задача, HTTPS |

## Что важно знать

- **Персональные данные.** В базе хранятся почты и профили студентов. По закону 152-ФЗ сервер с такими данными должен находиться в России, а до приёма реальных пользователей нужны политика обработки данных и уведомление Роскомнадзора.
- **Почта не подключена.** Сервер не отправляет письма: нет подтверждения почты и восстановления пароля. Пароль пользователю меняет администратор в админке.
- **Интерфейс пока не подключён.** Сайт `index.html` по-прежнему работает на данных в браузере. Подключение экранов к этому серверу — следующий этап.
